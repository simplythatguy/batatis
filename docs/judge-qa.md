# Batatis: The 22 Hardest Judge Questions

*Prepared for Submission 1 (Oct 29, 2026). Sources read Oct 20, 2026. Where we don't know something, the answer says so and names what would measure it. Evaluation figures are model-checked, not human-verified.*

**1. If Batatis gets something wrong and a variance is issued, who is liable?**
Batatis never states that a design complies or is safe; it checks whether an application is complete and cites the code. The decision stays with the SCO, who acts for the authority having jurisdiction, and the Council says that authority is the accredited organization, with SCOs exercising delegated powers on its behalf ([IB-2026-10-16](https://ebs.safetycodes.ab.ca/documents/webdocs/SR/IB-2026-10-16_AHJ_Clarification.pdf)). The Council also says registration in its portal is not approval and doesn't move responsibility for the decision away from the person authorized to issue it ([IB-2026-10-01](https://ebs.safetycodes.ab.ca/documents/webdocs/SR/IB-2026-10-01%20Orders%20and%20Variances%20Registration%20Changes.pdf)). Our product terms with any organization would say the same; we haven't had a lawyer review them yet.

**2. How accurate is it?**
Code identification: top-1 9/11 and recall@5 9/11 on the model-checked dev cases that have a gold article (in-sample, single run, 9 cases without gold excluded); the BM25 baseline gets 5/11; it asks the applicant on 40% of cases ([draft PR #12](https://github.com/simplythatguy/batatis/pull/12), dev cases, not real applications). For the engineer-needed flag in [PR #8](https://github.com/simplythatguy/batatis/pull/8): Engineer-needed flag (model-checked): rules_only 55/60 on the dev set (in-sample), 1 under-flag; shipped rules_plus_unknown: 50/60 in-sample, 0 under-flags, 27 unknowns sent to the applicant; held-out 7/8 blind (pre-fix), post-fix 4/8 (no longer blind) (PR #8, not merged). The held-out set is only 8 cases, and after a later fix it is no longer blind, so we don't report re-runs as held-out. No answer key has been checked by a person yet; a human-verified subset depends on someone writing answer keys.

**3. What stops it from inventing a code citation?**
The verifier keeps a citation only if its quote matches the code text in our database word for word; otherwise it's dropped. Section C objectives and functions are lookups from the code's attribution tables, not generated text. The three demo articles were checked against our code database. How often a correct article is dropped by this rule (the dropped-quote rate) is something we'll monitor in the benchmark and any pilot; it isn't measured yet.

**4. What does it cost to run per application?**
Identification cost and latency (measured, 20 dev cases × 3 repeats, identification step only (excludes the completeness judge and Section D); [draft PR #12](https://github.com/simplythatguy/batatis/pull/12), Oct 20, 2026): US$0.0197 = C$0.0277 per case at 1.4097 CAD per USD (Bank of Canada, Oct 19, 2026), about 0.02% of the C$125 floor; latency 5.7 s median, 11.3 s p95. Models are aliases (gpt-4.1-mini rerank, gpt-4.1 verifier), not pinned snapshots, and these are dev cases, not real applications. Completeness-judge cost (PR #11): to be measured. That run used the demo-build pipeline in PR #12 (not merged): local BM25 first, at no model cost, then an OpenAI rerank and verifier. Cost per real application, and the full pipeline including the completeness judge and Section D, are not yet measured.

**5. Why would an officer open it twice?**
We don't know yet; no officer has used it. It's designed so the officer can run the completeness check on any incoming package, not only ones made with Batatis, with gaps tied to form sections and the new Council documentation rules. Whether it saves time would be measured with our planted-gap protocol: the same package reviewed with and without the report, timed, counting gaps caught. The officer screen isn't built yet.

**6. How does this fit the SCC's new portal?**
From Dec 1, 2026, the Orders and Variances Portal is the only way to register variances, only SCOs can register, each variance is registered for one location, and the revised variance form and supporting documentation must be included ([IB-2026-10-01](https://ebs.safetycodes.ab.ca/documents/webdocs/SR/IB-2026-10-01%20Orders%20and%20Variances%20Registration%20Changes.pdf)). Batatis fills that revised form (engine built; the screen is in review) and is designed to produce a package the SCO uploads: form, attachment list and redaction flags [if merged: PR #11]. Batatis never registers anything itself, and registration is not approval: the Council says it doesn't move responsibility for the decision from the person who issues it. The Council says high-volume organizations may work with it on approved integrations, with technical requirements still to come, so any direct integration waits for those.

**7. Where does applicant data go, and which privacy law applies?**
For private applicants, Alberta's PIPA applies, and PIPEDA still applies to cross-border transfers such as calls to a model API outside Canada ([OIPC: PIPA](https://oipc.ab.ca/legislation/pipa/), [OPC](https://www.priv.gc.ca/en/privacy-topics/privacy-laws-in-canada/the-personal-information-protection-and-electronic-documents-act-pipeda/r_o_p/prov-pipeda/)). For municipalities, the Protection of Privacy Act has applied since June 11, 2025 ([OIPC: POPA](https://oipc.ab.ca/legislation/popa/)), and its obligations would flow to us by contract. Names and contact details are designed to stay in the case record and out of model prompts. OpenAI's Canada region stores data at rest in Canada but doesn't process it there, and Zero Data Retention needs OpenAI's prior approval, which we haven't requested yet ([OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data)).

**8. Can you legally use the building code text?**
We link to the code and quote it minimally, only to show the officer the exact wording a citation relies on, and we don't redistribute it. The code in force in Alberta is the National Building Code – 2023 Alberta Edition, 2nd printing, published Aug 17, 2026 ([Alberta.ca](https://www.alberta.ca/building-codes-and-standards)), and the code text comes from the National Research Council. We haven't obtained written terms from NRC for commercial use; that's a gate before any paid product.

**9. Does this only work in Edmonton or Calgary?**
The registration rules and the Council's form apply across Alberta, and Batatis fills that one form ([SCC form](https://ebs.safetycodes.ab.ca/documents/webdocs/PI/Variance%20Template%20final.pdf)). Each case records its jurisdiction and receiving authority, and the tool is designed so a local add-on (a city checklist or extra fields) is configuration; a per-jurisdiction form registry is in PR #12. Alberta has 433 accredited organizations ([SCC Annual Report 2025](https://ebs.safetycodes.ab.ca/documents/webdocs/SR/Annual%20Report%202025%20Final.pdf)); we've built for the provincial form, not for any one city's add-ons yet. Another province would need its own form map and code edition, which we haven't built.

**10. Who are your competitors?**
Code-search and plan-check tools such as UpCodes, CodeComply.Ai, InspectMind and Lawtonica check ordinary drawings or answer code questions; none of their public pages mentions preparing or reviewing alternative-solution applications ([UpCodes](https://cms-v2.up.codes/pricing), [CodeComply.Ai](https://codecomply.ai/), [InspectMind](https://www.inspectmind.ai/locations/canada-plan-check), [Lawtonica](https://lawtonica.ca/features)). Clariti's CivCheck checks document completeness and zoning rules for ordinary permits, and Calgary has tested it on residential permit applications ([Clariti case study](https://www.claritisoftware.com/resources/case-studies/how-calgary-is-using-ai-to-bring-consistency-to-one-of-canadas-most-complex-zoning-frameworks)), so it could add an alternative-solution module. The real status quo is code consultants preparing these by hand, and an official template and guide being developed by SSRIA and Build Forward Alberta ([SCC](https://www.safetycodes.ab.ca/a-step-forward-for-alternative-solutions/)), which we'd fill rather than compete with. Our "nobody does this" claim rests on public product pages as of Oct 20, 2026, so it's absence of evidence, not proof.

**11. Who pays, and how much?**
Our first buyer hypothesis is production homebuilders, because the person requesting an alternative solution supplies its Division C 2.3.1 documentation, now mandatory ([IB-2025-11-18](https://ebs.safetycodes.ab.ca/documents/webdocs/SR/IB-2025-11-18%20Mandatory%20Documentation%20of%20Variances.pdf)). The price to test is C$125–750 per bespoke package: one hour at the Council's C$125/hour alternative-solution rate up to two hours at C$375/hour, the top of a Saskatchewan engineering-rate guide used as a proxy ([SCC fee schedule](https://ebs.safetycodes.ab.ca/documents/webdocs/sr/council%20fee%20schedule%20asca%20v2.pdf), [ACEC-SK](https://www.acec-sk.ca/wp-content/uploads/2025/12/2026_Schedule_of_Fees_Summary.pdf)). No buyer has seen a price. Willingness to pay would be measured with price tests during a pilot.

**12. Will anyone adopt it, given that about half of variances are repeats?**
That's a real risk. On the Council's Data Hub, about half of article entries are jurisdiction-type variances rather than site-specific ones (1,514 site-specific of 3,118 entries, all disciplines), so builders may not need a new package each time ([SCC Data Hub](https://www.safetycodes.ab.ca/data-hub/variance-data/)). A "you may not need a variance" check against STANDATA and standing variances is planned, not built. Whether builders pay per package or per seat is untested; a pilot would measure it.

**13. Why can't a better general-purpose AI model replace you next year?**
A better model improves anyone's code search, including ours. It doesn't supply the form-version tracking, the Section C attribution layer with its citation validator, or a place in the officer's workflow, which has to be earned with each organization. Officer corrections collected in a pilot would add to that, under a data agreement with the organization, which would own its records.

**14. Has anyone actually used it?**
No. No real applicant or officer has tested Batatis, no pilot partner has agreed, and we have contacted no one. Usability findings so far come from scripted AI-agent walkthroughs, which we report as findings, not ratings.

**15. What happens after Demo Day?**
The target is a pilot run in parallel with one accredited organization during the program's Dec 2 – Mar 2 implementation window, which the program says isn't guaranteed ([onboarding guide](https://edmontonunlimited.com/wp-content/uploads/2026/09/Built-World-Challenge-Onboarding-Guide.docx.pdf)). That needs Canadian-region hosting, privacy terms the organization approves, and a scope under the C$75,000 threshold Edmonton and Calgary apply to competitive procurement ([Edmonton](https://www.edmonton.ca/sites/default/files/public-files/Procurement%20Standard.pdf), [Calgary](https://www.calgary.ca/buy-sell/supply-to-city/procurement-policy.html)). Success targets are fewer returns for more information than the organization's baseline and an officer review time below the manual baseline. If no organization engages, we keep building the applicant side.

**16. The brief asks for Appendix 1. Why does your export fill the SCC form instead?**
Since the brief was published, the Safety Codes Council has revised its Variance Form for Proposed Alternative Solution ([PDF dated Oct 6, 2026](https://ebs.safetycodes.ab.ca/documents/webdocs/PI/Variance%20Template%20final.pdf)). Its bulletin says "the revised variance form must be completed and included when the variance is registered through OVP", the only registration route from Dec 1, 2026, and registration is not approval ([IB-2026-10-01](https://ebs.safetycodes.ab.ca/documents/webdocs/SR/IB-2026-10-01%20Orders%20and%20Variances%20Registration%20Changes.pdf)). So an Appendix 1 application would have to be re-keyed before an officer could register it. Part 1 Sections A–D have the same structure on both forms, and we map them field by field; the differences are a re-worded Section B checkbox, the Section C and D layouts, and an owner acknowledgement that only Appendix 1 has and that we never tick for the owner. An Appendix 1-format export is planned, not built, if the judges need it.

**17. How has testing informed the design, and how will it inform the final version?**
So far, only through scripted AI-agent walkthroughs, not real users. The first two found concrete problems (an earlier front end with no way to start an application; a later one that opened someone else's example, blocked on "Not sure" and had no export), and those findings set the fixes now in review in [PR #16](https://github.com/simplythatguy/batatis/pull/16). The before → after re-run is a target and hasn't produced a result yet. Real-user rounds (first-time applicants, and officers on a planted-gap package) are written as a protocol with targets and begin only if a sponsor engages; none are scheduled.

**18. Does it name the benchmark acceptable solution, and is each article's rationale consistent with the code's structure?**
That is the design. Code identification is meant to return a ranked shortlist with the named Division B acceptable solution each departure is measured against [if merged: PR #12]; for example, the homebuilder's window is measured against Sentence 9.9.10.1.(2), at least 0.35 m² with no dimension under 380 mm, and the case's 0.312 m² opening is the departure (case files in [PR #14](https://github.com/simplythatguy/batatis/pull/14)). Section C objectives and functions are looked up from the code's attribution tables (on dev), so each row's rationale follows the code's own structure rather than generated text. Intent statements come from the national NBC 2020 Intent Statements, which aren't Alberta law, and where a lookup is missing the cell is flagged blank rather than filled.

**19. How does it know where to stop, and when is engineering required?**
The professional-involvement check (engine on dev) answers yes, depends or no and cites the Division C rule it relied on; when a deciding fact like span or storey count is missing, it asks rather than guessing (that refinement is in [PR #8](https://github.com/simplythatguy/batatis/pull/8)). It never writes a professional opinion, a test result or an engineering judgment. In the firestop case it is designed to say an engineering judgment is required where no tested system fits and list what it must contain, following the [IFC guideline](https://firestop.org/wp-content/uploads/2024/03/Guidelines_Firestop_Engineering_Judgments_Rev2024-02.pdf) that judgments aren't used in place of tested systems when those exist. That case hasn't been run through the engine yet.

**20. How does it signal its own confidence instead of filling boxes?**
Every fact carries a status and its source, and only confirmed facts are ever written to the exported form, draft or not (on dev, `engine/export/scc.py`). Missing or unconfirmed information shows up as a named gap with a question, and export is refused with reasons until those are resolved or the user takes a labelled draft. The one place it commits without asking is a narrow Part 9 auto-commit (probability ≥ 0.75, at most 3 articles), and that threshold is a placeholder, not yet calibrated; calibration needs a human-verified subset of test cases.

**21. Could a first-time manufacturer, contractor or homebuilder use it unaided?**
We don't know, because no real applicant has tried it. We wrote three demo cases, one for each type, and AI-agent walkthroughs playing a first-time applicant have not yet reached a finished export on the current screens. What would measure it is the protocol's target: at least 2 of 3 first-time applicants complete Part 1 A–D unaided, which needs real participants and isn't scheduled.

**22. Would a design lead choose this over their current process?**
Unknown. Today the alternative is preparing the form and the Division C 2.3.1 documentation by hand or paying a consultant, and Alberta has no published consultant price to compare against (we use the Council's own C$125/hour alternative-solution rate as an anchor, [SCC fee schedule](https://ebs.safetycodes.ab.ca/documents/webdocs/sr/council%20fee%20schedule%20asca%20v2.pdf)). Our bet is that arriving complete, with every citation traceable to the code text, is worth more than a blank form. We'd measure it in a pilot by comparing returns for more information against the organization's baseline and by whether applicants come back for a second package.
