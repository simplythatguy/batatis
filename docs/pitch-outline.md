## Part B. 3-minute demo narration

Recorded on `dev` after PRs #12, #14 and #16 merge; any step not merged is shown as "coming next" and said aloud. The end-to-end applicant flow is **not built**, so steps that depend on it are a labelled **cached demo run**. Engine steps that are on dev are shown through the engine's own API page. If the OpenAI switch (PR #12) hasn't merged, the run uses the keyless path (BM25 search, rule-based completeness, deterministic Section C) and the screen says so.

| Time | On screen | Narration |
|---|---|---|
| 0:00–0:15 | Title card | "Every variance in Alberta starts as a form a first-time applicant has never seen, and incomplete ones bounce back for more information. Batatis helps applicants arrive complete and helps officers check completeness. It never decides compliance." |
| 0:15–0:40 | Homebuilder case: description typed, facts appear with source tags **[if merged: PR #16]**; label "cached demo run" | "A homebuilder describes a two-storey Edmonton infill house. Batatis is designed to turn the description into facts you confirm, each tagged with its source. Where something is missing, the engine already names the field and asks a plain question instead of filling the box. The screens that join these steps into one flow are still being built, so this part is a cached run." |
| 0:40–1:15 | Ranked shortlist with the benchmark acceptable solution **[if merged: PR #12]**, cached demo run; then the Section C table (on dev) | "Code identification returns a ranked shortlist. For the bedroom window, the benchmark acceptable solution is Sentence 9.9.10.1.(2): at least 0.35 square metres, no side under 380 millimetres. The window in our demo case opens 0.312 square metres, so that's the departure. Section C is a lookup from the code's attribution tables, and any citation that doesn't quote the code word for word is dropped. The case files also flag what the tool's STANDATA check, still planned, will catch: slab edges, a roof that probably fails its STANDATA, and window fall protection." |
| 1:15–1:40 | Firestop case **[case files if merged: PR #14]**; professional-involvement result from the engine | "A contractor sealed 46 plastic pipe penetrations with a system listed only for metal pipe. Over three storeys, Clause 3.1.9.4.(4)(b) requires firestops tested to CAN/ULC-S115 with a 50 pascal pressure difference. Batatis is designed to point to tested systems first and, where none fits, say an engineering judgment is required, list what it must contain, and stop. Knowing where to stop is part of the product." |
| 1:40–2:00 | Engine API page: export returns 409 with a list of reasons; then a labelled draft PDF of the Oct 6, 2026 SCC form (engine on dev; screen **[if merged: PR #16]**) | "Export fills the Council's current form. | 2:00–2:45 | Engine API page: A–D gap list for an incoming package (on dev). Then the Officer screen with a drafted information request **[if merged: PR #16]**; if not merged, say "the officer screen is planned and not shown". Bulletin gates **[if merged: PR #11]** | "Now the officer's side. The same completeness review runs on any package and lists every gap by form section, with a fix hint, never a verdict on safety. For example, it flags a missing legal description, or a supporting document with no responsible person named. Officers can run it on packages not made with Batatis, and an applicant can run it before submitting. The officer screen that turns these into an information request is in review; until it merges, we don't show it. From December 1, variances go through the Council's portal, and registration is not approval." |
