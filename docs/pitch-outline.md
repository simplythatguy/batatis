## Part B. 3-minute demo narration

Runs on `dev`. Steps that need an open pull request are marked **[if merged: PR #N]**; if that PR hasn't merged by recording time, skip the step or show it as "coming next" and say so. The demo build runs on OpenAI end to end (BM25 first, then an OpenAI rerank and verifier). If that switch (PR #12) hasn't merged, the run uses the keyless path (BM25 search, rule-based completeness, deterministic Section C) and the screen says so.

| Time | On screen | Narration |
|---|---|---|
| 0:00–0:20 | Title card, then the empty Batatis start screen | "Every variance in Alberta starts as a form a first-time applicant has never seen. Incomplete ones bounce back for more information, and the officer reviewing them loses time on paperwork instead of safety. Batatis helps applicants arrive complete, and helps officers check completeness. It never decides compliance. Here are three first-time applicants: a homebuilder, a general contractor and, briefly, a manufacturer." |
| 0:20–0:55 | Choose "Homebuilder" → empty case **[if merged: PR #16]**. Type the infill-house description. Facts appear in the ledger with source chips | "A homebuilder describes a two-storey Edmonton infill house. Batatis turns the description into facts, each tagged with where it came from. Owner and site details come only from what you type or upload; it never guesses them. Where something is missing, it asks a plain question, with a short note on why the form needs it, instead of filling the box anyway." |
| 0:55–1:25 | Code check: cards for the slab, the roof and the bedroom window. Mark the window "Departure confirmed"; answer "Not sure" on one card | "Code check lines each requirement up against the actual code text. The heated slab and the unvented roof may already be covered by province-wide STANDATA, so you may not need a variance for them. Only the narrow bedroom window departs from Sentence 9.9.10.1.(2): 0.35 square metres, no side under 380 millimetres. And if you don't know yet, 'Not sure' becomes an open question that follows the case, instead of blocking you." |
| 1:25–1:50 | Section C table fills: article, objective, function | "Section C is a lookup, not a guess: objectives and functions come straight from the code's attribution tables, and any citation that doesn't match the code text word for word is dropped. Each row shows the article it came from, so an officer can check it against the code instead of trusting us." |
| 1:50–2:15 | Switch to the general-contractor firestop case **[case files if merged: PR #14]**. Professional-involvement result and Section D evidence list | "A contractor installed 46 firestops outside their tested scope. Sentence 3.1.9.1.(1) requires systems tested to CAN/ULC-S115. Batatis points first to tested systems. Where none exists, it says an engineering judgment is required and lists what it must contain, but it won't write that judgment. Knowing where to stop is part of the product. A manufacturer's case works the same way: product acceptance goes to CCMC, and the variance stays tied to one project." |
| 2:15–2:40 | Application screen: blocking-gap count. Click export → blocked with reasons; export a labelled draft PDF of the Oct 6, 2026 SCC form | "Export fills the Council's current form, dated October 6, 2026. While gaps remain, export is blocked and tells you why; you can still take a clearly labelled draft. The officer's Part 2 stays blank, because that decision belongs to the officer and their organization." |
| 2:40–3:00 | Completeness report with Div C 2.3.1 and one-location gates and the portal package list **[if merged: PR #11]**; otherwise show the A–D gap list | "From December 1, every variance goes through the Council's portal with its documentation. Batatis checks for the Division C 2.3.1 documentation and prepares the package; the officer decides and registers. Batatis: complete applications, faster reviews, and every decision left to people." |
