# Batatis: Pitch Deck Outline and Demo Video Summary

*Building Codes Challenge, Submission 1 (Oct 29, 2026). Status is as of Oct 22, 2026. Every number names its source, and each source is a file in this repository or a public document. Status words follow the Implementation Plan, §3: **built** (merged and reachable in the live app or API), **backend** (the API is merged and its screen is not finished), **roadmap** (not started). Evaluation figures are model-checked and mostly in sample, and none is human-verified. A slide shows a screen only if the screen is built. `C-market-provinces-business.md` is `docs/research/2026-10-20-vision/C-market-provinces-business.md`. The pitch deck PDF and `docs/pitch-deck/index.html` were made from an earlier version of these slides and are refreshed after the screens land.*

A context slide opens and the X Factor slide closes. `pitch-slides.md` has the on-slide text, the notes and the sources, and `pitch-narration.md` has the spoken script.

## Part B. Demo video (4:40, within the 4 to 5 minute slot)

`docs/demo/script.md` is the shot list and the narration for the demo video. It follows one fictional example from the applicant's sign-in to the officer's close-out, on the calm interface, and marks each step whose screen is not built yet as "pending UI" so that it is recorded only after the screen lands.

| Part | Time | What the viewer sees | Status |
|---|---|---|---|
| Applicant | 0:00 to 3:11 | Sign-up and onboarding. Describe the project. Check what we read. The questions. Code check with the code drawer. The applicant's own alternative-path cards. Section D and the engineer callout. Review. Application, draft or "Official PDF", submit | Built. The intake and code-check screens were walked only with the offline provider |
| Officer | 3:11 to 4:32 | Officer sign-in, queue, claim. The application sheet and completeness list. Package review findings and the drafted information request. Return, resubmit, accept as complete. Close-out record | Queue, claim, sheet, completeness, messages, accept and return are built. Package review and close-out wait for their screens |
| Close | 4:32 to 4:40 | What is built, what is backend, what is roadmap. "Batatis checks completeness. The officer decides." | |

Every frame that shows case data carries an EXAMPLE DATA overlay. People, companies and addresses are fictional.

**What the video does not show (say it if asked).** No real user or officer has tested Batatis. Code identification accuracy on the final pipeline is not measured. Coded rules for the most-varied articles exist as an unreviewed backend with no screen. The Calgary form, Part 2 prefill, standing-package checklists, the accuracy report page and other provinces are roadmap. Officer time saved has no measurement.
